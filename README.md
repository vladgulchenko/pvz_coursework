# Автоматизация работы пункта выдачи заказов

Курсовой проект Гульченко Владислава Михайловича, БГУИР.
Настольное приложение на русском языке для одного ПВЗ и одного рабочего компьютера.

Реализованы первоначальная настройка администратора, вход и выход, две роли,
учётные записи сотрудников, места хранения, регистрация и редактирование заказов
с позициями, поиск по номеру, фильтр статуса, выдача, оба пути возврата,
просрочка и история операций. Статус, размещение и история записываются атомарно.

## Требования

- Windows 10/11.
- .NET SDK **9.0.311** или более новый патч этой ветки, согласно global.json.
- Для работы в IDE — Visual Studio 2022 **17.14** с компонентами разработки
  классических приложений .NET.

Приложение использует **.NET 8**, WPF, MVVM, SQLite и EF Core **8.0.24**.
SDK 9 выбран из установленной среды; перехода приложения на .NET 9/10 нет.
Для запуска собранного приложения требуется .NET Desktop Runtime 8.
Пакеты закреплены в проектах и packages.lock.json.

## Сборка и запуск

Из корня репозитория в PowerShell:

```powershell
dotnet restore Pvz.sln --locked-mode
dotnet build Pvz.sln -c Release --no-restore
dotnet test tests/Pvz.Tests/Pvz.Tests.csproj -c Release --no-build --no-restore
dotnet run --project src/Pvz.Wpf/Pvz.Wpf.csproj -c Release --no-build --no-restore
```

В Visual Studio открыть Pvz.sln, назначить Pvz.Wpf запускаемым проектом и нажать F5.

При первом запуске создать администратора с собственными именем, логином и
паролем от 8 символов, затем войти. Общего пароля администратора нет.
Добавить место хранения и при необходимости сотрудника с ролью оператора.
После этого можно регистрировать заказы.

Дата и время вводятся в формате дд.мм.гггг чч:мм, в часовом поясе Windows.
В базе даты хранятся в UTC. У заказа должна быть хотя бы одна позиция и место
хранения; окончание хранения должно быть позже поступления. Номер и даты
после регистрации не редактируются. Выдача и возврат выполняются для заказа целиком.
При выдаче и завершении возврата место освобождается. После выдачи для возврата
необходимо заново выбрать место. Просрочка не меняет статус автоматически.

## База данных и миграции

Рабочая БД: %LOCALAPPDATA%\PvzCourse\pvz.db. Данные сохраняются между запусками.
Миграции применяются при старте. Перед изменением существующей схемы создаётся
папка резервной копии рядом с БД, включая существующие WAL/SHM/journal-файлы.
Повторный экземпляр программы для той же БД блокируется до её открытия.

Для отдельного демонстрационного набора можно явно задать другой файл:

```powershell
$env:PVZ_DATABASE_PATH = Join-Path $PWD '.local\demo\pvz.db'
dotnet run --project src/Pvz.Wpf/Pvz.Wpf.csproj -c Release --no-build --no-restore
Remove-Item Env:PVZ_DATABASE_PATH
```

Это отдельная база: в ней тоже нужно создать своего администратора.
Не удаляйте рабочую БД для обновления приложения.

Для разработки миграций:

```powershell
dotnet tool restore
dotnet ef migrations list --project src/Pvz.Infrastructure
dotnet ef migrations has-pending-model-changes --project src/Pvz.Infrastructure
dotnet ef migrations add MigrationName --project src/Pvz.Infrastructure --output-dir Data/Migrations
```

Design-time фабрика использует временный путь pvz-design-only.db, отдельно
от рабочей БД. Для применения миграций к рабочей базе используйте обычный запуск
приложения: он выполняет блокировку и резервное копирование.

## Структура

- src/Pvz.Core — сущности, перечисления, DTO и контракты сервисов.
- src/Pvz.Infrastructure — EF Core, миграции SQLite, сеанс, авторизация,
  администрирование и операции с заказами.
- src/Pvz.Wpf — представления, ViewModel, команды, ресурсы и запуск.
- tests/Pvz.Tests — тесты сервисов и ограничений настоящей SQLite без WPF.
- tools/Pvz.Smoke — отдельный Windows-прогон представлений и ViewModel.

Core не зависит от WPF и EF. Каждый вызов сервиса использует отдельный DbContext.
Права и активность сотрудника проверяются в сервисах. Пароли хешируются
библиотечным Identity PasswordHasher: формат V3, соль, PBKDF2, 210000 итераций.

## Проверки

На Windows с .NET 8.0.24 выполнены 41 тест сервиса/SQLite, 23 проверки WPF-прогона
и 6 проверок обычного запуска и сеанса.
Проверены в том числе граница срока хранения, повторные и одновременные выдачи,
одновременное понижение администраторов, FK/unique/check, резервная копия и
откат операции при искусственном сбое записи истории.

Дополнительный прогон UI выполняется отдельно от обычных тестов:

```powershell
dotnet restore tools/Pvz.Smoke/Pvz.Smoke.csproj --locked-mode
dotnet run --project tools/Pvz.Smoke/Pvz.Smoke.csproj --no-restore
dotnet run --project tools/Pvz.Smoke/Pvz.Smoke.csproj --no-restore -- --startup
```

Первый прогон открывает реальные WPF-представления, вызывает ViewModel и сервисы,
проверяет привязки и блокировку повторной команды. База временная, пароль
генерируется заново и не выводится. Изображения визуального дерева сохраняются
локально в docs/report/screenshots/, не попадая в git. Это проверка представлений;
системные диалоги подтверждения заменены тестовой реализацией.
Режим --startup проверяет обычный запуск приложения, первоначальную настройку,
смену экранов при входе и выходе и штатное закрытие окна на отдельной базе
в .local/startup-probe/. Временный каталог этого запуска удаляется после проверки.

Перед демонстрацией вручную проверить:

1. Создать администратора, войти, добавить оператора и место хранения.
2. Зарегистрировать заказ с позициями, найти его, изменить разрешённые сведения.
3. Отменить выдачу в диалоге: статус и история должны остаться прежними.
4. Подтвердить выдачу, принять весь заказ к возврату с причиной и новым местом,
   затем завершить возврат; проверить четыре записи истории и пустое размещение.
5. На другом заказе показать просрочку и путь возврата до выдачи.
6. Войти оператором, проверить отсутствие административных кнопок.
7. Запустить второй экземпляр для той же БД: он должен показать сообщение и закрыться.
8. Закрыть и снова открыть программу, проверить сохранение данных.

Ручная демонстрация с системными диалогами и сверка пояснительной записки
остаются отдельными действиями. Исходный комплект гайда и локальные материалы
курсовой исключены из git по указанию владельца проекта.
